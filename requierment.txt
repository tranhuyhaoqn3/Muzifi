Tài liệu yêu cầu: Web nghe nhạc / xem video cá nhân (Node.js, tối ưu iOS)
1. Tổng quan
Mục tiêu: web app tự host, dùng như "Spotify mini" cho một người dùng. Upload file hoặc dán link YouTube để tải về, tổ chức thành playlist, phát trên iPhone. Audio phải nghe được khi khóa màn hình.

Nguyên tắc cốt lõi: mỗi bài thuộc một loại duy nhất: audio hoặc video, quyết định lúc thêm vào (theo đuôi file khi upload; theo lựa chọn của bạn khi tải YouTube). Player tự chọn thẻ <audio> hoặc <video> theo loại.

Phạm vi: 1 user, mobile-first cho iOS Safari/PWA (iOS 16+), desktop chỉ cần dùng được.

Quyết định đã chốt

Mục	Quyết định
Người dùng	1 người, một mật khẩu trong .env
Định dạng lạ (mkv/webm/avi/wma…)	Tự chuyển đổi bằng ffmpeg (có cài đặt đổi sang "từ chối")
Backend / DB	Node.js 20+ (Express hoặc Fastify) / SQLite (better-sqlite3)
Frontend	Vanilla JS hoặc Svelte + Vite, PWA
Host	Máy nhà (mini PC, NAS, Pi), truy cập qua Tailscale hoặc Cloudflare Tunnel (HTTPS)
Ngoài phạm vi bản đầu	Tách audio từ video, nhiều user, chia sẻ, app native
Ưu tiên: M bắt buộc, S nên có, C làm sau.

4. Yêu cầu phi chức năng
Bảo mật: chạy yt-dlp/ffmpeg bằng spawn với mảng tham số (không ghép chuỗi shell); whitelist domain và chặn SSRF; lưu file theo UUID, chống path traversal; giới hạn loại/kích thước upload và kiểm tra bằng ffprobe; cookie Secure/HttpOnly/SameSite; helmet + rate limit; stream file phải qua kiểm tra đăng nhập.

Hiệu năng: stream trực tiếp từ đĩa bằng fs.createReadStream với range, không load cả file vào RAM; bắt đầu phát <2s trên LAN, seek <1s; thumbnail nhiều kích thước có cache header; ffmpeg/yt-dlp chạy ngoài luồng chính, máy yếu giới hạn 1 job nặng/lần.

Độ tin cậy: job lưu DB, khôi phục sau restart; dọn file dở dang; log có cấu trúc (pino), xoay vòng; sao lưu bằng cách copy thư mục data/ (media + SQLite).

Bảo trì: cấu hình qua .env (cổng, đường dẫn data, giới hạn, mật khẩu); có Dockerfile/docker-compose gói Node + ffmpeg + yt-dlp; có hướng dẫn cài đặt và cập nhật yt-dlp.

Tương thích: iOS Safari 16+ (chính), Chrome/Safari desktop, Android Chrome (best-effort).

5. Kiến trúc và công nghệ
Thành phần	Lựa chọn
Server	Node.js 20+ LTS, Express/Fastify
Database	SQLite (better-sqlite3)
Lưu file	/data/media, /data/thumbs, /data/tmp (trừu tượng hóa để sau đổi S3/R2)
Upload	busboy/multer, stream thẳng xuống đĩa
Metadata	music-metadata, ffprobe
Tải YouTube	yt-dlp (binary) + ffmpeg qua child_process.spawn
Hàng đợi	p-queue + bảng jobs
Tiến trình realtime	SSE hoặc polling 1–2s
Frontend	Vanilla JS/Svelte + Vite (vite-plugin-pwa)
Kéo thả	SortableJS (hỗ trợ touch)
Triển khai	Docker (hoặc chạy thẳng node) + Tailscale/Cloudflare Tunnel
Luồng dữ liệu

Upload: client → ghi file tạm → ffprobe phân loại → (nếu cần) job chuyển đổi → metadata + thumbnail → ghi DB.
YouTube: dán link → /youtube/info → chọn Audio/Video + chất lượng → tạo job → yt-dlp → xử lý → ghi DB.
Phát: client gọi /tracks/:id/stream (Range) → server trả 206.
6. Mô hình dữ liệu (không có user_id)
tracks: id, title, artist, album, duration_sec, media_type (audio|video), mime, file_path, file_size, thumbnail_path, width, height, source (upload|youtube), source_url, original_ext, created_at, last_played_at
playlists: id, name, created_at, updated_at
playlist_tracks: playlist_id, track_id, position
jobs: id, kind (youtube|convert), url, media_type, quality, status (queued|downloading|processing|done|error|canceled), progress, speed, eta, error, track_id, created_at, updated_at

settings: key/value (chính sách định dạng lạ, chất lượng mặc định, bước tua, số job…)

8. Lệnh tham khảo
Audio YouTube: -f "bestaudio[ext=m4a]/bestaudio" -x --audio-format m4a --embed-thumbnail --add-metadata
Video YouTube (≤720p): -f "bv*[vcodec^=avc1][height<=720]+ba[ext=m4a]/b[ext=mp4][height<=720]" --merge-output-format mp4
Chuyển video: ffmpeg -i in -c:v libx264 -c:a aac -movflags +faststart out.mp4
Chuyển audio: ffmpeg -i in -c:a aac -b:a 192k out.m4a
YouTube đổi thường xuyên (có thể cần thêm JS runtime cho yt-dlp), hãy đối chiếu tài liệu yt-dlp hiện hành khi cài.

10. Lộ trình và nghiệm thu
Phase 0: Prototype (làm đầu tiên) Trang tĩnh phát 1 m4a và 1 mp4 từ Node server có Range. ✅ Trên iPhone thật: khóa màn hình vẫn nghe; lock screen hiện tên bài và nút; seek chạy; audio→audio khi khóa máy; thử audio→video; thử PiP.

Phase 1: MVP Đăng nhập, upload (tự phân loại, chuyển đổi định dạng lạ), thư viện, player đầy đủ (loop, seek, ±10s, tốc độ, shuffle), playlist kéo thả, nhớ trạng thái. ✅ Upload 20 file lẫn audio/video, tạo playlist, nghe liên tục 1 giờ khi khóa màn hình, không mất tiến trình.

Phase 2: YouTube Dán link → chọn Audio/Video + chất lượng, hàng đợi job có tiến trình, playlist YouTube, hủy/thử lại, cập nhật yt-dlp. ✅ Tải 1 audio, 1 video 720p, 1 playlist 10 bài; tất cả phát được trên iPhone.

Phase 3: Hoàn thiện PWA đầy đủ, queue nâng cao, sleep timer, Docker, sao lưu, tách audio từ video (nghe nền cho video), cache offline.
